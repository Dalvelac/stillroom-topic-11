SQL injection in catalogue search

Can a product name change the structure of the database query?

Catalogue searchReflected search textOrder and receipt ownershipFulfilment permissions

Step by step

  1. Open the catalogue as a guest. Visit page two, then choose Coffee and sort by ascending price. Search for Roaster's.
  2. Read the response in HTTP history. The search returned 200 and the results contained one product, Roaster’s Reserve. A successful response establishes the behaviour of this input.
  3. Open the query source. Both the count and product-list statements use placeholders. The server selects a complete sort expression from a fixed map and binds the page limit and offset.
  4. Run the focused tests below. They capture the exact statement text and arguments. Changing the term from Roaster's to Daybreak preserves both statements. An unsupported sort selects the predefined default.
Result for this fixtureThe two sampled terms changed the bound values while the prepared statement text stayed identical. The sort allowlist and the tests account for the two places where query construction differs.

An ordinary 200 or a search error alone cannot establish how the database parsed a query. The source and statement-level assertions supply that evidence.
