Evaluation and conclusion

The strongest evidence depended on the question being asked. Tool output, browser behaviour and server-side assertions each answered a different part of the investigation.

Web application findings

Burp’s side-by-side history made it possible to point at the exact encoded string in a specific response. ZAP surfaced that reflection on its own and supplied a rule ID and confidence level. Reviewing its lead required reading the actual HTML and checking the DOM. mitmdump preserved the order of the fulfilment exchanges in a form that could be read offline after the browser closed.

All three captured the complete ordinary journey. A history entry can substantiate a request, a status or a literal response value. Establishing that a peer cannot read an object required two resources and four identities. Establishing correct fulfilment required holding the transition fixed for the permission check, then holding the actor fixed for the sequence check. That additional evidence came from the shop and its tests.

Infrastructure findings

Nmap recorded FTP open before the change and closed afterward. Metasploit preserved the baseline inventory. The Wireshark capture showed a successful file retrieval, and a separate HTTP request confirmed the catalogue was still available after FTP was disabled.

Conclusion

The four tested controls held for the recorded build and fixtures. The reflected-XSS lead illustrates why raw alert counts make a poor measure of tool effectiveness. The tools had identical measured route coverage, different strengths for triage, and measurable loopback latency above the direct path. For this testbed, ZAP was useful for discovering the lead, Burp for explaining it to a reviewer, and mitmdump for preserving transaction order. The infrastructure run exposed a similar limit in service discovery. The label on port 8770 needed confirmation from the shop’s HTTP response. Wider application coverage and human review time remain unmeasured.

Student opinion and contribution

The student will add their own opinion and contribution here.

I’d choose Burp Suite. Both Burp and ZAP worked well for intercepting traffic, but Burp felt more complete for the way I like to investigate a finding. The moment that shaped my opinion was reviewing the shop’s search page. ZAP flagged the search term as a possible reflected XSS issue and marked the alert as low confidence. In Burp’s HTTP history, I could see the request beside the raw response and check both places where the search term appeared. In each place, the shop had encoded the angle brackets. What I liked about Burp was how easily I could trace a specific input through to the response and explain why I wouldn’t report it as XSS.
