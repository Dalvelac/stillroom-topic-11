Reflected XSS in search results

Does the reflected search term become markup in either of its two output contexts?

Catalogue searchReflected search textOrder and receipt ownershipFulfilment permissions

Step by step

  1. Search for the harmless text Morning <sample> & "notes". The browser displayed the original characters in the results heading and in the search field.
  2. Inspect ZAP rule 10031. The run recorded alert ID 8 on parameter q, message 18, at Informational risk and Low confidence. The screenshot shows the same rule on the apostrophe search. The exported alert links the angle-bracket example to its exact message.
  3. Read Burp history entry 16 in Raw view. Search for &lt;sample&gt;. Both matches sit inside HTML, one in a text span and one in a quoted input value. The ampersand and quote characters are encoded too.
  4. Compare the raw response with the DOM recorded during navigation. The span had one text node, zero child elements, and the original text. The input retained the entire marker as one value. Run the reflection regression to verify the exact emitted strings.
Result for this fixtureReflection is present. Treating the alert as a confirmed reflected-XSS vulnerability would be a false positive for the two tested outputs. ZAP correctly identified an input worth inspecting.

This conclusion covers the heading and quoted field in this server-rendered search page. A script, URL or other output context would require its own review.
